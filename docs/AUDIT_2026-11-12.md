# Delivery reliability audit — 2026-11-12

Baseline: `56f579c`, main after Claude's PRs #1–#5. Those PRs were reviewed and
retained except for the link-sharing behavior that contradicted the original-post
forwarding requirement. Branded cover, typography, collapsible conditions,
application buttons, source list and the measured Gemini model order are unchanged.

## Findings addressed

1. **High: send succeeded, database save failed, next run sent it again.**
   Added a durable intent/claim/acknowledgment/completion journal before Telegram.
   Acknowledged sends reconcile database writes without resending; unknown sends
   stop for inspection. Reminder flags use the same protocol.
2. **Medium: nine accepted cards still generated two public digests.**
   Daily reservation uses Tashkent date. One card selection must fit rich, legacy
   rich and HTML in one message. Overflow remains retryable. A completed daily
   run exits before source fetching, link resolution or AI calls.
3. **Medium: Groq-only URL selection returned before calling Groq.**
   The provider guard now accepts either configured provider. Returned URLs still
   must exactly match supplied candidates.
4. **UX: custom share button sent a permalink, not the original post.**
   Removed it. Telegram's native Forward is the actual original-post operation;
   bot payloads do not protect channel content against forwarding. No duplicate
   copy-link or application links were introduced.
5. **Operational: an entirely unverifiable AI batch could finish green.**
   An empty batch with failed eligibility evidence now raises an error and leaves
   those source URLs retryable. An intentional, verified no-match remains valid.
6. **Operational: partial HTML delivery returned the same False as zero delivery.**
   Partial rich/legacy/HTML delivery now raises `DeliveryUncertain`, preserving the
   journal claim rather than releasing it for replay.

## Verification

- Offline suite on Python 3.11 and 3.13, including crash windows and concurrency.
- Ruff undefined-name/error checks and additional F checks on changed Python files.
- Rich-block schema check against the maintained Bot API subset.
- Bandit: zero medium/high severity findings (three pre-existing low findings).
- Installed runtime dependency scan: no known vulnerabilities.
- Live Supabase probe: isolated namespaced row exercised insert, conditional claim,
  acknowledgment, completion and repeat suppression. Zero Telegram writes, zero
  grant writes; the probe row was removed and its absence confirmed.
- GitHub CI and end-to-end dry-run results are recorded in the release PR.

## Practical limits

Telegram does not offer an idempotency key for these send methods. An uncertain
HTTP response or a crash after claiming requires reconciliation; automatically
retrying would reintroduce the duplicate window. This is not exactly-once delivery.
See [the recovery procedure](delivery-journal.md).

The baseline's database access/RLS configuration and annual-cycle deduplication
limits remain separate concerns documented in the previous audit. This release
does not rotate credentials, grant new database access, rewrite historical grants
or claim that all worldwide opportunities are covered. AI eligibility quotes are
checked against collected source text; they are not a substitute for the official
programme's complete admissions conditions.
